# Android 通用操作技能 · 四大能力

> 配套 [SKILL-v2.md](SKILL-v2.md)（协议与失败分类）。本文件只讲四件事：
> **点击 · 滑动 · 屏幕读取 · 文字输入**，参数均为本机实测值。

**基准设备**：OnePlus IN2010　1080×2400　增益 1:1　校准 `cal 1 1 0`

---

# 一、点击

## 1.1 五步规程（不可合并）

```
① 定位  hover(x, y) 或 mouse_move       只移动，不点击
② 校验  重新截一张图 → 读该图的 input.pointer  与目标比差，容差 30–40px
                                        ★ 每次点击前都必须执行，禁止复用旧截图
③ 校准  calibrate_pointer(1, 1, 0)        移动会清掉校准，必须重做
④ 点击  mouse_click()                     原地，不移动
⑤ 验证  screenshot → 比对状态变化          计数/页面/toast
```

## 1.2 三条硬规则

| 规则 | 原因 |
|---|---|
| **每次点击/输入之前必须截图确认光标位置** | 不复用任何旧图；确认项 = 画面里控件确实在目标处 + `input.pointer` 坐标落在控件内 |
| **禁止 `android_tap(x, y)`** | 内部「移动+点击」一体，没有确认落点的机会 |
| **禁止未校验就点** | 指针位置靠推算，实测累积误差可达数百像素 |

### 「截图确认光标位置」的判定标准

一次合格的确认必须同时满足三条：

1. **新图**：本次动作前重新调用截图，`frameAgeMs` 是新的，不是上一轮留下的
2. **画面**：截图里目标控件处于可点击状态（不是弹窗遮挡、不是禁用灰态）
3. **坐标**：该图 `input.pointer` 的 `x/y` 与目标坐标差 ≤ 40px

三条缺一即视为**未确认**，必须回到①重新定位，不得点击。

> 为什么强调"新图"：光标静止数秒会被系统隐藏，旧图既看不到光标、`pointer` 也是上一状态；
> 用旧图确认等于没确认。

## 1.3 坐标换算

| 项 | 值 |
|---|---|
| 命令接收 | **全分辨率像素**（1080×2400） |
| 预览图缩放 | 预览 838 宽 → 真机 1080，**×1.289** |
| 校准值 | = 1/增益。手机 `1 1 0`；2 倍增益平板 `0.5 0.5 0` |

## 1.4 控件尺寸与落点选择

| 控件 | 建议落点 |
|---|---|
| 图标（❤ ★ 💬 搜索） | 图标**正中**，容差 ±40px |
| 按钮（关注/发送/搜索） | 文字居中处，避开左右边缘 20px |
| 卡片/笔记封面 | 封面中央，**避开标题文字**（文字可能触发长按菜单） |
| 输入框 | 框内偏左（避开右侧相机/清空图标） |

> 实测教训：点笔记**标题文字**会弹出「内容反馈/不符预期」菜单，点**封面**才正常进帖。

## 1.5 屏幕边缘是不稳定区

y < 300 区域做小步相对移动会被边缘钳制吸附：

- 给「向上 −145」→ 反而更深贴到 y≈39
- 连续微调后指针直接不可见

**对策**：边缘控件一律用**绝对 `hover` 一步到位**，不要用相对小步逼近。

## 1.6 点击无效的四种真因（按概率排序）

| 症状 | 真因 | 处理 |
|---|---|---|
| 点了没反应 | 校准被清掉（`scaleX: null`） | 点前重做 cal |
| 点了没反应 | 未武装（`armed: false`） | `hid_arm` |
| 变成滚动/拖拽 | 移动与按下合并 | 点击前静置 ≥0.35s |
| 点了别的控件 | 落点偏 | 回到①重新定位 |

# 二、滑动

## 2.1 参数

| 参数 | 实测值 | 说明 |
|---|---|---|
| 起止点 | (540, 1900) → (540, 700) | 竖直上滑 1200px，居中不碰边缘 |
| 时长 | **350ms** | 太短会变成惯性甩动 |
| 连续间隔 | **≥ 250–400ms** | 低于此值固件**整批丢弃**（曾 24 次全丢） |
| 单次上限 | 5 次一组 | 超过后需重新取帧 |

## 2.2 何时用滑动、何时用别的

| 场景 | 做法 |
|---|---|
| 信息流翻页 | `sswipe` 上滑，一组 3–5 次 |
| 帖子内滚到评论区 | 同上，但要**滚 2–3 次**才到评论区 |
| 视频帖看评论 | **滑动无效**（播放页不滚动）→ 点右下 💬 图标开评论面板 |
| 横向切换（图片/标签页） | 短滑 300px + 时长 250ms |
| 页面内精确滚动一屏 | 不用滑动，直接用双指？否——用单次长距离滑 |

## 2.3 判断滑动是否真的生效

滑动**不返回内容变化**，必须截图比对：

- 内容换了 → 生效
- 内容一模一样 → 可能已到底 / 可能整批被丢

> 实测：连续快速 swipe 会全部静默丢弃，画面毫无变化但无任何报错。**间隔是唯一解**。

# 三、屏幕读取

## 3.1 三个信息源

| 来源 | 能给什么 |
|---|---|
| `android_screenshot` | JPEG 原图 + `width/height/rotation` + `frameAgeMs` + `input` |
| `input` 字段 | `armed` / `calibrated` / `scaleX` / `scaleY` / `pointer{x,y}` / `positionEstimated` |
| `android_control` 的 `actionResult` | 同上 + 本次动作结果 |

## 3.2 读指针用坐标，不要找灰圈

```json
"input": { "pointer": {"x": 999.0, "y": 600.0}, "positionEstimated": true,
           "calibrated": true, "scaleX": 1.0, "scaleY": 1.0 }
```

**Android 会在指针静止数秒后自动隐藏光标**。稍慢一步截图就看不到灰圈，会被误判成"没移到位"，于是在同一位置反复纠正、越纠越偏。

**做法**：`hover` 后截一张，读 `input.pointer`，与目标比差。

## 3.3 分辨率与坐标系

| 设备 | 截图尺寸 | 预览尺寸 | 换算 |
|---|---|---|---|
| 手机 | 1080×2400 | 838×1862 | **×1.289** |
| 平板 | 3040×1904（横） | 1596×999 | **×1.905** |

> 旋转（横竖屏）会让**所有历史坐标失效**，并清掉校准，必须重测。

## 3.4 用截图确认"事情真的发生了"

不要相信 `actionCompleted: true`——它只代表指令下发。用可观测的状态变化判定：

| 动作 | 可验证的痕迹 |
|---|---|
| 点赞 | ❤ 计数 +1 且图标变实心红 |
| 收藏 | ★ 计数 +1 且变金色 + 「收藏成功」toast |
| 关注 | 按钮文案「关注」→「已关注」 |
| 评论 | toast「评论已发布」+ 💬 计数 +1 + 列表出现内容 |
| 搜索 | 结果页出现分栏（全部/用户/商品/图片）+ 筛选行 |
| 进帖 | 出现作者栏 + 底部 ❤/★/💬 计数 |
| 返回 | 上一页的元素重新出现 |

## 3.5 时间参数

| 等待 | 值 |
|---|---|
| 点击后到截图 | **≥ 1.2s**（等界面稳定） |
| toast 类反馈 | 1.5–2.2s 内截图，否则消失 |
| 滑动后到截图 | ≥ 0.9s |

# 四、文字输入

## 4.1 能力边界

| 项 | 实测结论 |
|---|---|
| ASCII | ✅ `android_type` 可输入，数字/英文正常 |
| 中文 | ❌ **直接拒绝**，返回无图无报错 |
| 字符重复 | v2 已改善（`nice` 干净），但仍需**回读输入框校验** |
| 单键 | `android_key` 单击可靠（菜单导航已验证） |
| 长按按键 | 仅 `android_key_report` + `keycode=0` 释放 |

## 4.2 输入前必须先聚焦 + 先截图确认

**文字输入同样适用「点击前截图确认」规则**——因为输入的第一步就是点输入框。

| 步 | 动作 | 确认方式 |
|---|---|---|
| 0 | **截图确认** | 新图里输入框可见、未被弹窗遮挡；`input.pointer` 落在框内 |
| 1 | 五步规程点中输入框 | 出现光标 / 键盘弹出 / 占位符消失 |
| 2 | **再截图确认焦点** | 画面出现输入态（光标、工具条、发送按钮） |
| 3 | `type` | 回读输入框内容逐字核对 |

> 输入前的截图确认不只看指针，还要确认**输入框已经是焦点态**——
> 否则字符会打到页面上、触发搜索或翻页，而不是进输入框。

## 4.3 中文怎么办：拼音 → 应用自带搜索建议

**这是本项目验证过最可靠的中文输入路径。**

```
① 点搜索框聚焦
② type "huaibei"            ← 打拼音，不是中文
③ 小红书搜索建议直接给出中文：淮北 / 淮北美食 / 淮北烫面 …
④ 继续 type "caier" 收窄     → 淮北采耳 / 淮北采耳店 / 淮北采耳哪家好
⑤ 点中建议项                  ← 用五步规程
```

要点：

- **不需要切输入法**，靠应用自己的联想词表跳转
- 拼音要**连写不加空格**（`huaibeicaier`）
- 建议列表命中率很高：`huaibeicaier` 直接给出 15 条淮北采耳相关词
- 建议项点中即触发搜索，不必再点「搜索」按钮

## 4.4 提交类输入的完整闭环

以评论为例：

| 步 | 动作 | 校验 |
|---|---|---|
| 1 | 点评论输入框 | 出现「有话要说…」+ 工具条 |
| 2 | `type "nice"` | 输入框出现 `nice`，**逐字核对** |
| 3 | 观察发送按钮 | 空输入时浅粉**禁用**，有内容后变**红色可用** |
| 4 | 点发送 | 五步规程 |
| 5 | 验证 | toast「评论已发布」+ 💬 计数 +1 |

> 发送按钮的颜色变化本身就是一个可靠的前置校验：**没变红 = 没输进去**。

# 五、四能力速查

```
点击    hover → **新截图读 input.pointer 确认** → cal → mouse_click → 截图验证
        ★ 每次点击前必须截图确认光标位置，禁止复用旧图
        禁止 tap；边缘 y<300 用绝对定位；点封面不点标题

滑动    (540,1900)→(540,700) dur 350ms，间隔 ≥250ms，5 次一组
        视频帖不滚动 → 点 💬 开评论面板

读取    截图拿原图 + input 三件套（armed/calibrated/pointer）
        光标会静止隐藏 → 用 pointer 坐标校验，别找灰圈
        用计数/文案/toast 验证效果，别信 actionCompleted

输入    仅 ASCII；**先截图确认输入框焦点态**再 type；回读校验
        中文 = 拼音 + 应用搜索建议（huaibeicaier → 淮北采耳店）
        发送按钮变红 = 文字确实进去了
```
