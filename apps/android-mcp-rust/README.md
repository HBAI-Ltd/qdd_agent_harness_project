# Native Android MCP bridge

[简体中文](README.zh_CN.md)

This independent Rust workspace ports the Windows device operator from
`apps/android-mcp`. It embeds the operator/settings pages and the 22 MCP tool
schemas captured in [the TypeScript baseline](docs/typescript-baseline.json).
The existing TypeScript implementation remains available for comparison.

The release is one Windows x64 EXE. End users do not need Node.js, a Rust
toolchain, a separate browser engine, or a serial native addon. The existing
system browser displays the operator; JPEG/PNG target previews run in a bounded
worker process launched from the same EXE. Phone screen sharing and ESP BLE HID
remain on their existing devices.

## Build and validate

Development uses Rust 1.87+ with the Windows MSVC linker, and the repository's
Node 24/npm 11 tools. Cargo dependencies are pinned in `Cargo.lock`. The Windows
build statically links the C runtime and enables size optimization, LTO and
symbol stripping.

Every Cargo build also runs `tools/prepare-assets.mjs` with pinned **esbuild
0.28.2**. Install npm dependencies first; set `QDD_NODE` to an explicit Node path
when it is not on PATH. Readable `assets/` sources remain unchanged. Cargo's
`OUT_DIR` holds parser-minified JS/CSS (including settings inline code), compact
JSON and HTML with only structural indentation removed. DOM hooks, attributes,
inline spacing and pre/textarea content are preserved. The build ID covers the
pipeline, minifier version/options and actual generated bytes; packaging refuses
an EXE whose identity differs from regenerated current sources. Node is required
only for development, never to run the delivered EXE.

From the repository root:

```powershell
npm ci
npm run check:android:rust
npm run test:android:rust
npm run build:android:rust
npm run test:exe --workspace @qdd/android-mcp-rust
node apps/android-mcp-rust/tools/test-assets.mjs
node apps/android-mcp-rust/tools/test-generated-ui.mjs
```

The normal repository `build`/`typecheck` commands continue to cover TypeScript.
The separate Rust commands cover this native workspace; no TypeScript project
reference is needed for a Cargo package.

Generated files live under `build/` and stay out of Git:

- `build/windows/设备操作台.exe`: standalone delivery file.
- `build/windows/设备操作台.zip`: a single-entry ZIP, without local settings.
- `build/windows/manifest.json`: EXE/ZIP sizes, SHA-256, build identity and measured
  Flash capacity comparisons.
- `build/windows/exe-smoke.json`: packaged fixture validation results.

When an older EXE is in use, set `QDD_RUST_OUTPUT_DIR` to an absolute independent
version directory (for example `F:\aidol\qdd_agent_harness_project\apps\android-mcp-rust\build\windows\v43`)
and run `npm run size --workspace @qdd/android-mcp-rust` and `test:exe` with the
same value. The default output stays unchanged and the running old version need
not be stopped. Update a stdio MCP configuration to the new executable path to
use that version.

## Offline installation and legacy USB receiver

Connect the ESP, computer and controlled phone to the same wireless network,
then open the ESP root page at `http://<device-IP>:3334/`. The three-step page
provides manual previous/next navigation and direct Windows ZIP or Android APK
download. No Internet connection or local HTML receiver is required.
The USB endpoints below remain only for compatibility, outside the ordinary guide.

`build/usb-browser/v55/设备USB接收.html` is a self-contained JS/CSS receiver that
does not require running a native downloader first. The ESP retains the attachment
at `/qdd-usb-receiver.html`; the old `/usb-receiver` page now redirects to the LAN
download homepage. Plain device-IP HTTP has no serial permission: save the
HTML, open it in desktop Chrome/Edge, click to select the board, and save the ZIP
after transfer and SHA-256 verification. Extract it and run the console.
Initially obtaining HTML needs the web connection or a pre-distributed file;
receiving is offline once the HTML is available.

```powershell
node apps/android-mcp-rust/tools/prepare-usb-receiver.mjs
node apps/android-mcp-rust/tools/test-usb-receiver.mjs
```

Run from the repository root. Sources are in `assets/usb-receiver/`; pinned
esbuild produces the HTML and a source/output identity manifest. Only the
existing QDDDRV/1 INFO/READ/CANCEL operations are used. There is no control input,
serial signal change or EXE launch. Progress, cancellation, disconnect and errors
are visible. Read-only block retries have attempt and total-time limits; invalid
CRC, offset, session or whole-file SHA prevents saving an incomplete ZIP.
Browser/OS serial support and physical board transfer remain separate device
checks; host tests do not substitute for them.

## Transfer archives

The single-EXE `设备操作台.zip` is the compressed runtime download and contains no
local connection settings. The optional `android-mcp-rust-source.zip` is a separate
development snapshot with an explicit source allowlist, pinned Cargo files and
required public test fixtures. It excludes builds, caches, dependencies, logs and
private settings, and includes build instructions and a per-file hash manifest.

To audit an existing release and reproduce its source archive with Python 3.8+:

```powershell
python tools/pack-transfer.py --artifact-dir build/windows/v47
```

The tool checks ZIP filename/CRC, extracts to an empty temporary directory,
verifies the exact EXE hash and runs `--self-test` without starting a service.
It writes `transfer-compression-audit.json` beside the archives without changing
the release EXE or its existing `manifest.json`. Source entries use fixed times
and sorted paths; identical inputs and Python/zlib versions reproduce the ZIP.
The audit also regenerates compressed assets with the pinned Node/esbuild tools
and compares every build input with the archived source. Standalone source ZIPs
include their npm/Cargo preparation instructions; local settings remain excluded.

## Usage

Double-click the EXE to configure the phone and ESP addresses. `--no-browser`
keeps the service in the console. Configuration uses the same adjacent
`qdd-android.json` or `%LOCALAPPDATA%/QDDAndroid/config.json` format as the
TypeScript desktop program. Unknown configuration fields are discarded.

```powershell
.\设备操作台.exe --configure
.\设备操作台.exe --no-browser --config .\qdd-android.json
.\设备操作台.exe --stdio --config .\qdd-android.json
.\设备操作台.exe --self-test
```

HTTP MCP is served at `http://<PC-LAN-IP>:8790/mcp`; the browser operator is at
the same origin's `/`. The service accepts only local/private network peers,
Host values and Origins. It never uses ADB as an input fallback. A physical
emergency stop can only be cleared on the ESP device.

## Pointer targeting and calibration

Some tablets omit the system mouse cursor from screen capture. A `hover` image
then cannot confirm the actual pointer location. Identical `probe` images return
`measurable:false` / `measurementAvailable:false`, both images, paused input and
no `probeId`. Never invent `finish` cursor centers or assume every device has a
pointer gain of 2.

Prefer the updated phone App's user-opened **Pointer calibration** page. Keep it
in the foreground, take `android_screenshot`, then call
`android_pointer_calibration` with `{"phase":"auto","frameId":"..."}`.
Check `measurementSource:"android-mouse-events"` and `calibrated:true` before
returning to the target App and observing its screen again.

`auto` reads actual mouse-event coordinates from `/pointer/calibration`. It
reveals the pointer with a small movement, settles for 550 ms, then measures a
default 96 HID counts toward the screen center and computes counts/pixel for
both axes. It never clicks or opens a page. The calibration page draws the
actual event marker into screen capture. Lost focus, rotation, missing/stale
events, edge clipping or intervening mouse movement pause input without
overwriting an existing calibration. Android acceleration can still affect
later coordinates. Use `android_preview_tap` to inspect the simulated target and
zoom; that preview does not prove the physical pointer has reached the target.

Both `android_preview_tap` images visibly render `PHONE PX: X=... Y=...` in original
phone pixels, including the 2x crop. The 52px bottom caption and any right padding
are annotations, not phone content. `annotation.original` / `annotation.zoom`
describe canvas dimensions, `sourceRect` and `legend` bounds; content stays at (0,0),
with target centers, `crop`, `zoomTarget` and `tapArguments` unchanged. The caption
does not obscure the target, move the real mouse, click or take over input ownership.

Button presses wait until 350 ms after the most recent successful movement ACK,
subtracting time already elapsed. The wait is cancellable, does not replay
input, and requires no extra AI-side sleep. `move` dx/dy uses HID counts;
`tap` / `hover` / `swipe` use original screen pixels. `CONFIGURING`, paused input
and ACK timeouts are instrument failures, not target-App test failures. Home/Back
ACKs confirm accepted HID reports only; verify OEM navigation in a new image.

## Single input, retransmission and Unicode

ASCII typing, single keys, clicks and Home/Back use a short pulse: neutral release
is sent about 50 ms after the press is actually written, **without waiting for its
ACK**. Each report retains its own original 1200 ms ACK deadline. A delayed ACK
therefore cannot intentionally extend a short press into a hold/system repeat.
Cancellation releases earlier; timeout never resends the press or remaining
characters. Raw `key_report` / `mouse_move buttons` can still express intentional holds.

A `tools/call` request ID cannot be reused in the same MCP session after dispatch
starts, including success, failure or cancellation. Only its 32-byte digest is
retained; arguments, images and response bodies are not cached. The 4096-ID limit
fails closed and requires a new session, rather than evicting records and allowing
old replays. Identical text with two new IDs remains two intentional inputs. This
does not identify arbitrary new-ID retries as old actions: observe uncertain
outcomes instead of blindly repeating them.

Text containing non-ASCII uses the updated ESP's encrypted BLE text channel and
the phone App's QDD IME. The user must enable/select that IME and focus an editable
field. Missing firmware/IME fails clearly, without substituting pinyin, ADB or
network-based remote input. Validate the whole UTF-8 string, no NUL, at most 512B.
`QDDTXT/1` checks the editor epoch, uploads contiguous chunks, and sends COMMIT
once. Its queued ACK is not successful input. Only STATUS is polled for up to
10 seconds until phone acceptance/rejection; PING and safety deadlines stay unchanged.
Disconnect, cancellation, timeout or changed focus after commit reports
`textTransfer.status:"uncertain"`, never automatic resubmission. `accepted` means
the InputConnection API accepted the request; inspect the new real image and
intended field to verify actual content.

## Tests and migration scope

Rust unit tests live next to the modules in `src/*.rs`; `cargo test --locked`
checks parsing, image limits, coordinate timing, ordered acknowledgements,
cancellation, session ownership and device-discovery validation. The tests use
loopback fixtures and never open a real device's serial port.

`tools/test-exe.mjs` retains the frozen TypeScript EXE acceptance scenarios.
The Node-specific packaging assertions and test-helper imports were adapted,
with additional invisible-cursor and calibration-page precondition checks. It uses the official JavaScript MCP SDK with fake
phone HTTP streams and a fake ESP TCP endpoint, including an empty PATH and a
Chinese/space-containing executable path. These checks do not establish live
BLE, physical pointer accuracy, or a real multi-MiB ESP download.

See [the size assessment](docs/size-assessment.md) before choosing a storage
partition. This package does not alter ESP firmware or flash the device.
